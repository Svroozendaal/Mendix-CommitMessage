# CONVENTIONS
## Format, naming, gates, and state

---

## File format

### Agents
File: `.agents/agents/<name>.md` (lowercase kebab-case)

Required sections:
```markdown
---
name: <name>
description: <one sentence — used for routing>
status: full | skeleton | deprecated
---

## Purpose
## Input
## Behaviour
## Output
## Gates
```

### Skills
File: `.agents/skills/<name>/SKILL.md`

Required sections (full):
```markdown
---
name: <name>
description: <one sentence>
status: full
---

## Purpose
## Input
## Output
## Steps
## Notes
```

Skeleton format (only `## Purpose`):
```markdown
---
name: <name>
description: <one sentence>
status: skeleton
---

## Purpose
[One paragraph: what does this skill do and when is it used?]
```

**Rule:** I/O sections (`## Input`, `## Output`, `## Steps`) are only added when a skill is promoted to `full`. A skeleton has only `## Purpose`.

### Dev-library topic skills (registration exception)

Topic skills under `.agents/skills/dev-library/<topic>/SKILL.md` (one technology or recurring pattern each) are registered **only** in `.agents/skills/dev-library/index.md`, not in `manifest.md` or `SKILLS.md`. The dev-library as a whole has a single row in the main registries. Topic skills follow the format defined in the dev-library index; they are created by the development-agent (internet research with permission, saved after user approval) or manually via `/brain`.

**Status values:** `full` (implemented), `skeleton` (purpose only), `deprecated` (superseded; kept for reference, never routed to — the description must name the successor).

## Gates

Gates are explicit pause points where you (the user) give approval before the agent continues.

| Gate | When | What is approved |
|---|---|---|
| **Approach gate** | Before any code is written (loose-mode dev) | The intended approach, affected files, pattern |
| **Diff gate** | After all code changes | The diff overview (`diff.md`) |
| **Per-improvement gate** | Each entry in improvement-backlog | One entry at a time: yes / no / revise |

**Rule:** agents pause at every gate and explicitly ask for approval: "Do you want to continue? (yes / no / revise)"

---

## State (`/.work/<ticket>/`)

One folder per ticket: `/.work/<ticket>/`

Ticket naming: lowercase kebab-case, e.g. `feat-42-user-auth`, `bug-17-login-redirect`. Derive from your issue tracker's key format.

Files written during development work:
- `diff.md` — summary of all code changes (Gate artifact)

Persistent brain-level files (outside `/.work/`, version-controlled):
- `.agents/improvement-backlog.md` — accumulated improvement proposals
- `.agents/CHANGELOG.md` — applied-improvement log (written by flow-developer)
- `.agents/reflections/<ticket>.md` — archived reflections (optional)

**Gitignore:** `.work/` should be in `.gitignore`. Approved reflections are archived to `.agents/reflections/`.

## Generic vs. app-specific

| Content | Location |
|---|---|
| Generic workflow (agents, skills, commands) | `/.agents/` |
| App-specific knowledge (knowledgebase, libraries, components) | `/.app-info/` |

**Rule:** `/.agents/` never contains app-specific content. Skills *reference* `/.app-info`; they do not copy its content.

---

## Knowledgebase structure

The knowledgebase is the app knowledge source for context-aware skills.

```
/.app-info/knowledgebase/
  index.md          # top-level entry point: section map + quick-scan table
  overview.md       # high-level app summary
  glossary.md       # domain terms, role slugs, field keys
  kb-manifest.md    # machine-readable sync state
  <sections>/       # organised by domain area
    index.md
    <topic>.md
    _summary.md     # auto-generated by kb-sync
```

`kb-manifest.md` schema (one row per synced module):
```markdown
| module | source | kb_full | kb_summary | source_hash | last_synced | summary_generated | status |
```
`status` is `ok` / `stale` / `missing`.

## Skill loading model

Agents load skills **explicitly by path**. No tool auto-discovery.

Path format: `.agents/skills/<name>/SKILL.md`

Commands in `commands.md` are wired into Claude Code via `.claude/commands/`. Each command file loads the relevant agent by explicit path.

---

## Naming

- Agent files: `<name>.md` (lowercase kebab-case)
- Skill folders: `<name>/` (lowercase kebab-case), file always `SKILL.md`
- Ticket folders in `/.work/`: lowercase `<ticket-id>` matching your issue tracker format

---

## Language

All files in `/.agents/` are written in **English**.
App-specific content in `/.app-info/` follows the app's own language conventions.
